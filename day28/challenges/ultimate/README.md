# AsyncAggregator — 并发爬取聚合系统

> Day 28 终极挑战 | 难度：★★★★★

## 目标

使用 `asyncio` 和 `aiohttp` 构建一个高并发异步爬取系统，支持任务调度、信号量限流、多级缓存（内存 + 文件）、自动重试和结果聚合。

## 功能要求

- **CrawlTask / CrawlResult 数据模型**：封装任务配置（URL、解析器、优先级、重试）和执行结果（成功/失败、耗时、是否缓存）
- **Cache 双级缓存**：内存字典缓存 + JSON 文件缓存，基于 TTL 过期策略
- **信号量限流**：使用 `asyncio.Semaphore` 控制最大并发数
- **异步爬取**：
  - 单任务执行：缓存检查 → 信号量获取 → 异步请求（带重试）→ 解析响应 → 统计记录
  - 批量并发：`asyncio.gather` 执行所有任务，异常隔离
- **结果聚合**：合并数据、统计分析、趋势分析
- **报告生成**：Markdown 格式，含数据概览表格、各数据源详情、统计摘要和 ASCII 图表
- **统计信息**：总任务数、成功/失败/缓存数、总耗时、平均耗时

## 验收标准

- [ ] `Cache` 内存缓存和文件缓存均在 TTL 内有效
- [ ] `fetch()` 在并发超过 `max_concurrent` 时正确排队
- [ ] 请求失败时按 `max_retries` 自动重试
- [ ] `crawl_all()` 并发执行所有任务，单个失败不影响整体
- [ ] `aggregate()` 正确合并结果并生成统计
- [ ] `generate_report()` 输出包含表格和统计的 Markdown
- [ ] `get_stats()` 返回准确的运行时统计
- [ ] 所有 TODO 注释处均已实现
