# Day 75 终极挑战：完整文档问答助手

## 项目名称
**DocChat —— 多轮对话式文档问答助手**

## 目标
在 Day 74 文档解析的基础上，构建一个支持多轮对话、引用溯源、查询改写、重排序的完整文档问答助手，并提供生产级 RESTful API。

## 功能要求
1. **查询改写器**：
   - 指代消解：将"它的作者是谁"改写为具体文档名
   - 查询扩展：为短查询添加上下文关键词
   - 多查询生成：一个问题生成 3 个变体，合并检索结果
2. **检索 + 重排序管道**：
   - 初步检索：向量搜索 Top-20
   - 重排序：Cross-Encoder 或 ColBERT 对 Top-20 精排
   - 截断：取 Top-5 送入 LLM
   - 可选：HyDE（假设文档嵌入）增强检索
3. **多轮对话管理**：
   - 对话历史窗口管理（滑动窗口 + 摘要压缩）
   - 追问支持：自动识别指代关系
   - 对话摘要：长对话自动压缩为摘要，释放上下文窗口
4. **引用溯源**：
   - 答案中的每个关键陈述标注来源（文档名 + 页码 + 原文片段）
   - 支持点击引用跳转到原文位置
   - 置信度标注：高/中/低置信度
5. **LLM 生成增强**：
   - System Prompt 模板化（角色/指令/格式要求可配）
   - 流式输出：逐 token 推送答案
   - 结构化输出：支持 JSON 格式返回（含答案 + 引用 + 置信度）
6. **FastAPI RESTful API**：
   - `POST /chat`：多轮对话（接收 conversation_id + message）
   - `POST /upload`：上传文档（支持批量）
   - `GET /search`：纯检索（不经过 LLM）
   - `GET /conversations`：对话列表
   - `DELETE /conversations/{id}`：删除对话
   - WebSocket `/ws/chat`：实时流式对话
7. **对话持久化**：
   - 对话历史存入 SQLite / JSON 文件
   - 支持对话恢复和导出
8. **反馈机制**：
   - 用户对回答点赞/点踩
   - 反馈数据用于后续评估和优化
9. **速率限制与鉴权**：
   - API Key 鉴权
   - 按用户的速率限制
10. **监控与日志**：
    - 请求日志（输入/输出/耗时/token数）
    - Prometheus 指标导出

## 验收标准
- [ ] 多轮对话上下文保持 ≥ 10 轮
- [ ] 引用溯源标注准确，可追溯到原文
- [ ] 查询改写在追问场景下提升检索准确率 ≥ 15%
- [ ] 流式输出延迟 < 500ms/token
- [ ] RESTful API 全部端点可用且有 Swagger 文档
- [ ] WebSocket 实时对话正常工作
- [ ] 对话持久化和恢复功能正常
- [ ] 反馈数据正确记录
